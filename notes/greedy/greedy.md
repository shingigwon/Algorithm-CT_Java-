# [그리디 (Greedy)](https://en.wikipedia.org/wiki/Greedy_algorithm)

현재 상황에서 가장 좋아 보이는 선택을 반복해 최적해를 구하는 방식.
<br>
매 순간 최선의 선택이 전체 최선임을 보장할 수 있을 때 사용한다.

---

## 적용 상황

| 상황 | 키워드 |
|------|--------|
| 최소 동전 개수 / 최소 횟수 | 가장 큰 것부터 선택 |
| 회의실 배정 / 구간 스케줄링 | 종료 시간 기준 정렬 |
| 최소 비용으로 목표 달성 | 정렬 후 순서대로 |
| 묶음 / 그룹 최적화 | 정렬 후 인접 원소 처리 |

---

## 그리디 적용 조건

두 조건을 동시에 만족해야 그리디 적용 가능.

- **탐욕적 선택 속성(Greedy choice property)** : 앞의 선택이 이후 선택에 영향을 주지 않는다
- **최적 부분 구조(Optimal substructure)** : 부분 문제의 최적해가 전체 문제의 최적해를 구성한다

> 동전 문제에서 큰 단위가 작은 단위의 배수가 아니면 그리디 보장 안 됨  
> ex. 500 / 400 / 100 → 그리디 : 500+100×3, 최적 : 400×2

## 문제 해결 단계

1. **선택** : 현재 상태에서 최적의 선택
2. **적절성 검사** : 선택이 문제 조건을 만족하는지 확인
3. **해답 검사** : 문제가 해결됐는지 확인, 안 됐으면 1번 반복

## 핵심

- 그리디 적용 전 반례 먼저 찾기 → **반례 없으면 적용**
- **정렬이 핵심** - 대부분 정렬 후 순서대로 처리
- DP로 풀 수 있는 문제도 그리디로 풀리는 경우 있음 (더 빠름)
- 배수 관계 보장 → 그리디, 아니면 DP (ex. 1/5/10 → 그리디, 1/400/500 → DP)
